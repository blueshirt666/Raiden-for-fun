# TapeOut #260 — 4 位与 8 位拼接进位加

链上任务 ID `#260`（题库序号 293）。`S[8:0] = B[7:0] + A[3:0]`，A 零扩展。

## 为什么是这道题

`K_task ≡ 参考实现门数`，`C_ref ≡ 门数 × 深度³`（在 15 道题上逐条核对通过）。
所以 q 顶满时：

    性价比 = H / 烧掉的NAND = (n + 4K)/n = 1 + 4 × (参考门数 / 我的门数)

即"性价比最高"等价于"参考实现面积虚胖倍数最大"。#260 用 938 门做一件 52 门
的事，虚胖 18×，是第二名（#253，7.2×）的 2.5 倍。

## 交付

| 文件 | 门数 | 深度 | C = A·d³ | C_ref/C | 烧 NAND | H(P=1) | H/n |
|---|---|---|---|---|---|---|---|
| `tapeout_260_v1_*` | 52 | 18 | 303,264 | 48.3× | 52 | 3,804 | 73.2 |
| `tapeout_260_v2_*` | 64 | 14 | 175,616 | 83.5× | 64 | 3,804 | 59.6 |

V1 = 最省 NAND（性价比最高）。V2 = C 更小的保险版，仅在现任榜主 C < 303,264
时才需要动用。两版 q 都顶满 4.0。

`a_first` / `b_first` 是两种引脚排布假设（4 位操作数在前 / 8 位在前），
功能相同，选与画布实际引脚顺序匹配的那个。

## 结构（V1，52 门）

- bit0：半加器 5 门
- bit1..3：全加器 9 门 ×3 —— `t=NAND(p,c)` 同时供进位和和，复用 `¬g`
- bit4..7：高半只是把 c4 当增量传播，退化成半加器 5 门 ×4
- s8 = c8，直接复用高半最后一个进位门，零额外开销

9 个输出天然就是末尾 9 个门（LSB→MSB），**不需要任何缓冲门**。
